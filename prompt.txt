isi planning:

buat table users:
id int pk
name varchar(255) not null
email varchar(255) not null
password varchar(255) not null // password merupakan hash dari bcrypt
created_at timestamp default current_timestamp



buatkan API untuk registrasi userbaru dengan endpoint POST /api/v1/auth/register
buat sebuah logik uniqueness di email dan password harus di encrypt menggunakan bcrypt

    request body:
    {
        "name": "John Doe",
        "email": "[EMAIL_ADDRESS]",
        "password": "password"
    }

    response success:
    {
        "success": true,
        "message": "User created successfully",
        "data": {
            "id": 1,
            "name": "John Doe",
            "email": "[EMAIL_ADDRESS]",
            "created_at": "2022-01-01T00:00:00.000Z"
        }
    }

    response failed:
    {
        "success": false,
        "message": "User already exists",
        "detail": "[technical error jika ada]"
    }


buatkan API untuk login user dengan endpoint POST /api/v1/auth/login
    request body:
    {
        "email": "[EMAIL_ADDRESS]",
        "password": "password"
    }

    response success:
    {
        "success": true,
        "message": "User logged in successfully",
        "data": {
            "token": "[token]",
            "user": {
                "id": 1,
                "name": "John Doe",
                "email": "[EMAIL_ADDRESS]",
                "created_at": "2022-01-01T00:00:00.000Z"
            }
        }
    }

    response failed:
    {
        "success": false,
        "message": "Wrong password",
        "detail": "[technical error jika ada]"
    }



struktur folder di dalam src
gunakan pendekatan Domain Driven Design (DDD) modular:
src/
│
├── api/              # Endpoint routes (v1/auth)
│   └── v1/
│       └── auth/
│           ├── register.ts
│           └── login.ts
│
├── application/      # Business logic & domain services
│   └── auth/
│       ├── register.service.ts
│       └── login.service.ts
│
├── domain/           # Business entities & value objects
│   └── user/
│       ├── user.entity.ts
│       └── user.error.ts
│
├── infrastructure/   # Infrastructure concerns
│   ├── db/           # Drizzle schema, migrations, connection
│   ├── jwt/          # JWT utilities
│   └── bcrypt/       # Password hashing utilities
│
└── main.ts           # Application entry point & setup
